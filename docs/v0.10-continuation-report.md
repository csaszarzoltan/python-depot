# PythonDepot v0.10 Continuation Report

## Scope and user value

v0.9 introduced persistent projects, but users still had to copy dependency data from a project into the upgrade planner and package comparison workspace. v0.10 closes this workflow gap by making the saved project snapshot reusable through contextual next actions.

## Requirements implemented

- **BR-10-01, Must:** Saved project context must reduce repeated data entry across frequently used workflows.
- **UR-10-01, Must:** A user can open the Python upgrade planner from a project with the latest dependency input already populated.
- **UR-10-02, Must:** A user can open package comparison from a project with detected package names already populated.
- **UR-10-03, Must:** A user can open the risk inbox with the current project name applied as the search query.
- **FR-10-01, Must:** Upgrade launch accepts a target Python query parameter and defaults to 3.13.
- **FR-10-02, Must:** Comparison candidates are deterministic and reuse the latest immutable snapshot.
- **FR-10-03, Must:** Missing project context returns a clear 404 instead of an empty or misleading workspace.
- **UX-10-01, Must:** Project detail presents the three next actions as a contextual, keyboard-operable navigation group.
- **A11Y-10-01, Must:** The action group has an accessible navigation label and visible focus styles inherited from the shared controls.
- **PRIV-10-01, Must:** Launch telemetry may include only project ID and workflow type, never repository/source text or package names.
- **TEST-10-01, Must:** Context reuse is developed test-first and all prior focused product regressions remain green.

## Implementation details

- Added `track_project_workflow()` with a strict workflow allowlist.
- Added contextual actions to Project detail: upgrade analysis, dependency comparison, and project-filtered risks.
- Added `GET /workspace/projects/{project_id}/upgrade`.
- Added `GET /workspace/projects/{project_id}/compare`.
- Reused existing deterministic project snapshots, upgrade parser, decision renderer, and risk query behavior rather than duplicating logic.
- Added `tests/test_product_ui_v10.py`.

## TDD and validation

All new acceptance tests were written before implementation. Four failed against v0.9 and the missing-project test already passed because unknown routes returned 404. After implementation, the complete focused product regression across v0.10 through the original product capabilities reports **40 passed**. Changed Python files pass Ruff. Editable installation, route behavior, telemetry privacy, and final ZIP integrity were validated.

## Deferred

The next logical increments are project-linked risk storage rather than text search, project-to-policy evaluation, repository-provider imports, lockfile upload, authentication-backed project ownership, and production database migrations.
