# PythonDepot v0.9 Continuation Report

## Scope and user value

The previous versions improved risk triage but users still had to re-enter dependency context in separate workflows. v0.9 introduces the first persistent Project Workspace so a team can save application context once, re-import dependencies, and understand what changed between snapshots.

## Requirements implemented

- **BR-09-01, Must:** Project dependency context is reusable rather than repeatedly pasted into disconnected workflows.
- **UR-09-01, Must:** A user can create a named project with a repository/source identifier and requirements-style dependencies.
- **FR-09-01, Must:** Initial creation automatically persists the first immutable snapshot.
- **FR-09-02, Must:** Re-import appends a snapshot and reports added, removed, and constraint-changed packages.
- **FR-09-03, Must:** Unsupported editable or URL lines are counted for review instead of silently treated as analyzed.
- **UX-09-01, Must:** The Projects screen provides useful empty and populated states plus a direct creation form.
- **UX-09-02, Must:** Project detail shows current dependencies, source context, snapshot history, and a re-import form.
- **A11Y-09-01, Must:** Dependency tables use captions and keyboard-focusable overflow containers.
- **REL-09-01, Must:** Project imports are append-only and never overwrite historical snapshots.
- **PRIV-09-01, Must:** Project telemetry records only project ID and dependency count, not source text or dependency content.
- **TEST-09-01, Must:** New project behavior is test-first and prior product regressions remain green.

## Implementation details

- Added `projects` and `project_snapshots` SQLite tables.
- Added creation, listing, detail, and append-only import services.
- Reused the conservative requirements parser introduced in v0.7.
- Added package constraint extraction and deterministic alphabetical presentation.
- Added FastAPI create, detail, and import routes using POST-Redirect-GET.
- Added project list/detail renderers and made Projects a top-level workspace navigation item.
- Added `tests/test_product_ui_v09.py`.

## Validation

All five new tests failed before implementation. After implementation, the v0.9, v0.8, v0.7, original UI, and product-capability focused regression completed with **35 passed**. Changed files pass Ruff. Editable installation, project route smoke tests, and ZIP integrity were also validated.

## Deferred

Repository-provider connections, lockfile upload, project-to-upgrade prefill, project-to-policy SBOM evaluation, project risk summaries, authentication, role-based access, and production database migrations remain future increments.
